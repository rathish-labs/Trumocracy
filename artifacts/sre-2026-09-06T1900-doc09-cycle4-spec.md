## Boundary rule — enforced mechanically, not by attention

Two of the three Mediums this spec closes were **boundary errors in the previous spec**: a FIND
dropped the first line it consumed and appended a line it never consumed, twice. The cycle-3
self-check ("the simulated applier applied all ops cleanly") could not see either, because a
clean apply proves the anchors matched and nothing about whether the result reads correctly.

Every op below was generated by a builder that **refuses to emit the spec** unless:

1. the FIND matches **exactly once** in the current file;
2. **every line the FIND consumes reappears verbatim in the REPLACE** — counting multiplicity, so
   a duplicate cannot be silently created or dropped — unless that line is declared as rewritten
   and the change is named in the op intent;
3. **REPLACE[0] == FIND[0]** and **REPLACE[-1] == FIND[-1]**, unless the op records a reason.

Nine of the thirteen ops go further: their REPLACE is **derived from the FIND** by exact
substring substitution, so their boundaries cannot be wrong by construction. The builder rejected
an early draft of OP 13 for an undeclared edited line; that is the check working.

**What this spec does NOT do.** It does not reopen or weaken the `REL-LIM-18` closure, the
`FR-131` word ban (six versions clean), the HALTED / deployed-nowhere posture, the durable-claims
restructure of §0 or the now-reproducible changelog — all verified correct at cycle 3. It does not
touch Docs 03, 04, 07, 08 or the memory index. The release verdict is unchanged.

## Why this spec exists

The approver (Rathish, 2026-09-02) found in Doc 09 the same **Critical** class that failed
Doc 14 v1.0.0: an anonymity claim that v1 does not deliver, asserted in a **public-facing
material**. `FR-131` (Doc 02 §4.45, closing sentence) is explicit — the v1 product, its UI,
its README and all public-facing materials MUST NOT use the words "private", "anonymous",
"receipt-free" or "secure" to describe v1 voting behaviour, and MUST NOT present v1 as
providing the Definition-B (v2) cryptographic guarantees. Release notes are a public-facing
material. The trigger site is line 148: *"Your vote in this release is anonymous, but it is
not yet receipt-free."*

The whole document was swept for **three violation classes**, matching the three that Doc 14
carried:

1. **Anonymity / privacy overclaims about v1 voting** — corrected to the `FR-131`(a)–(d)
   disclosure and kept consistent with the approved Doc 14 v2.3.0 §2.6 language, including its
   **future-framing** (voting does not exist as a working screen yet; here is what WILL be true
   the day it ships).
2. **Tamper-evidence / public-record overclaims** — Doc 14's `ISS-C2-01` class, corrected to
   the shipped v1 truth: append-only **inside Trumocracy's own store**, not published, not
   independently checkable until the `DES-097` audit-anchoring release.
3. **Two-tier omission** — the open-tier / counting-tier model (`FR-122`, `FR-123`,
   `FR-131`(d), `FR-132`) was absent from Doc 09 entirely and is added wherever the document
   makes a participation claim.

Plus a small set of **facts that are now false and therefore mislead** (Docs 07/08 "do not
exist"; "Docs 02–14 unreviewed"; stale Doc 06/14 versions).

**The release verdict is NOT touched.** Release `0.1.0` stays **HALTED** and Gate 2 stays
**not approved**. Where §0 and §7 preconditions are restated, they still fail — for the
*correct* reason (122 of 138 Must rows OPEN) rather than the stale one (the RTM does not
exist). That is a strengthening, not a rewrite.

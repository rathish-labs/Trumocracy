`docs/08-traceability-matrix.md` on disk by line range; no anchor was retyped. Every `REPLACE` was
derived from its own `FIND` by a single checked string substitution or by appending whole lines, so

## The cycle-3 Medium, and why the fix is a method and not a sentence

The v2.12.2 changelog asserted, present tense and in bold, **"§6 is not edited at all"**. That was
**false**: v2.12.2's tenth changed line is old **1930** / new **2055** — the `v2.12.0 DoD check`
paragraph — and that is a **§6** line.

**What aggravates it is that the v2.12.2 dry-run list recorded the claim as *verified*.** It could
only do that because the check asked **"did §8 change?"** — the label the cycle-2 review report
attached to that line, which the v2.12.2 OP-8 heading then inherited — instead of asking the **file**
which section contains the line. The verification ran against a section boundary taken from a
**label**. A label is not evidence, and no number of careful checks can repair a check pointed at the
wrong place.

### How section boundaries are derived in this spec — the command, and its output

```
$ grep -n '^## ' docs/08-traceability-matrix.md
```

The section containing line *n* is the **last heading at or before *n***; the section ends one line
before the next heading. Nothing else is consulted — not a spec, not a review report, not an
operation heading.

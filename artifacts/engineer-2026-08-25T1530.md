### STEP 2 — SDK service layer (`packages/sdk/src/`)

**`party-creation.js`** — NEW; injectable store seam mirroring IEligibilityVerifier pattern:
- `InMemoryPartyStore`: Maps for drafts/petitions/parties/members; IS_INSECURE_MOCK()=true;
  archived petitions are immutable (ARCHIVED_IMMUTABLE error on update attempt).
- `PartyCreationService(store, clock)`:
  - `createDraft`: validateDraft → collision check (name + emblem, same jurisdiction,
    vs live petitions + active parties) → cooldown check → saveDraft.
  - `publishDraft`: server-side validateDraft re-run → savePetition (PETITION state).
  - `expirePetitions`: scans PETITION-state rows, archives those past closesAt.
  - `activateParty`: stub-level saveParty (legalRegistrationVerified: false).
  - `joinParty`: NO verifyEligibility call; FR-130 cap enforced unconditionally (no bypass,
    no grace period per D2); lifts only via `recordLegalRegistration`.
  - `recordLegalRegistration`: ONLY cap-lifting path; sets legalRegistrationVerified: true.
  - `partyStatus`: returns memberCount, provisional, cap (null when verified), capReached,
    legalRegistrationStatement (BR-020 disclosure).

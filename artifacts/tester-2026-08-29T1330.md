## Doc 08 v2.5.0 — the six status calls, with reasoning

**FR-024 → COMPLETE (unchanged), evidence extended.** Already closed; gains the v1
application-tier proof that the authoring rule takes no approver/reviewer/reason and that content
is never judged (every declared tier is accepted).

**FR-079 → CLOSES.** DES-103 closes the chain; no SCR needed because FR-079 carries no UI clause.
Every clause separately tested: exactly three tiers with no nameable fourth; automatic Supporter on
join; `votingWeightForTier()` returns **1 for every tier**, so no configuration can differentiate
weight (FR-021 intact); unknown tier refused **loudly** rather than defaulted. The "differentiated
eligibility per vote type" clause is a **permission, not an obligation**, and the single such rule
(the authoring gate) is published and code-checked.

**FR-090 → CLOSES.** DES-104 + SCR-12. Public authorship, any-Worker-may-compete, and equal
standing are each proven **positively and as capability-absence**: no withdraw/reject/reorder/
demote/merge/veto path for the first author; no weight/rank/priority field; `isOriginal` is
provenance only. The detail that convinced me the guarantee is whole rather than nominal:
**differently-phrased spellings of one question group into ONE window** — without that, "equal
standing in the same window" is defeated by rephrasing. Carries a **revisit flag** for §10.13.13
open question (b).

**FR-080 → does NOT close. G-TRACE → G-NOMECH.** The self-declaration half is built and tested.
Rule 4 fails on the informed-consent clause: FR-080 requires the UI to state plainly **before a
declaration is confirmed** that Worker status is **permanent for the term** *and* makes the
participation record **public for the duration of the term**. I read the shipped copy
(`workerGateHow`): *"Doing so makes what you put forward public for the term"* — that addresses
publicity narrowly, for *what is put forward*, and states **permanence nowhere**. There is also
**no confirmation step** — the declare control opens the filing form directly, so "before…
confirmed" has no moment to attach to. **Rule 1 also fails**: FR-080 carries an explicit UI
obligation, so it needs an `SCR`, and DES-103 binds none.

**FR-091 → does NOT close. G-TRACE → G-NOMECH.** The **order** guarantees are complete and
genuinely strong (eight stages one step at a time; skip refused *naming what was skipped*;
reversal refused; no-op refused; unknown stage rejected rather than treated as position zero;
`advanceStage()` takes no target/force/skip/actor). Rule 4 fails on "transitions executed by code
**per published timelines**": `governance.js` `schedule()` exists but is **not wired** into the
service — I checked, it appears only in a doc comment — and the demo advances by a button. Doc 06
§7 #25 records it as owed. The anti-capture half is done; the automation half is not.

**FR-092 → does NOT close. G-TRACE → G-NOMECH.** The trail is genuinely append-only (ordered,
un-rewritable, no delete path, copies on read, injected clock). Rule 4 fails **twice**:
**(i)** FR-092 enumerates the **vote result, enacted consequence, implementation status and
measured outcome**, and this layer records none of them — TC-3558/UT-0845 asserts the service
never casts, stores or counts a vote, which is *correct design* and simultaneously leaves four of
seven enumerated elements with no recording mechanism; **(ii)** third-party reconstruction from
public data alone needs DES-097 anchoring (Doc 06 §7 #24, Doc 13 S-8). The drop does not paper
this over — the surface states plainly that the record is not yet independently checkable
(UT-0883), which is the honest posture and also the reason the row cannot close.

**FR-122 / FR-123 → stay G-PHASE3**, evidence extended (open-tier may deliberate; refusal carries
`stillAMember`/`mayStillDeliberate`; BINDING_VOTE admission as the only seam call site; coercion
notice before the ask; service holds no vote).
